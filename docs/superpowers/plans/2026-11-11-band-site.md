# Band Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A phone-first website on Netlify's free plan where the band keeps cover songs (imported from Ultimate Guitar links, transposed to one shared key), gig setlists, and mp3s of unreleased songs.

**Architecture:** A Vite + React single-page app talks to Netlify Functions (v2, `export default (req: Request) => Response`) under `/api/*`. Functions store JSON records and audio chunks in Netlify Blobs behind a small key-value interface, so they can be tested against an in-memory store. Chord parsing and transposition are pure TypeScript modules shared by the app and the functions.

**Tech Stack:** TypeScript 5.6, React 18.3.1, react-router-dom 6.28.0, Vite 5.4, Vitest 2.1 + @testing-library/react 16, @netlify/blobs 8.1, @netlify/functions 2.8, netlify-cli for local dev.

**Spec:** `docs/superpowers/specs/2026-11-11-band-site-design.md`

## Global Constraints

- No login. Every page and API route is open to anyone with the address (the user's decision). Keep all storage access inside `netlify/functions/lib/` so login can be added later in one place.
- Hosting: Netlify free plan only. No other services or accounts.
- One agreed key per song (`bandKey`). Transpose changes it for everyone. There is no per-phone transpose.
- Chord view follows Ultimate Guitar's layout (see Task 8) but uses none of its name, logo or branding. The site title is "Band Book" (my call; easy to rename in `src/app/config.ts`).
- Link import accepts only `https://tabs.ultimate-guitar.com/...` and `https://www.ultimate-guitar.com/...` URLs. It must never fetch any other host.
- Audio: mp3 only (`audio/mpeg`), max 25 MB per file, uploaded in 3 MB chunks (3_145_728 bytes) to stay under Netlify's ~6 MB function request limit.
- Phone first: base font 16px, chord sheet 15px monospace minimum, tap targets at least 44px tall, no horizontal page scroll at 360px width (the chord sheet itself may scroll horizontally).

## Review Focus

1. A pasted link that is not an Ultimate Guitar page, or is a UG tab (not chords) page: the user sees "That link isn't an Ultimate Guitar chords page" and no request leaves for other hosts. (Task 5 tests.)
2. Ultimate Guitar blocks the request or changes its page: import fails with "Couldn't read that page. Paste the chords instead." and the form switches to the paste box with the link kept. (Tasks 5 and 7 tests.)
3. Chords with accidentals, extensions, slash bass and brackets (`Bbmaj7`, `F#m7b5`, `C/G`, `(G)`) transpose correctly, and lyric words like "A" in a lyric line are never treated as chords. (Tasks 2 and 3 tests.)
4. An mp3 bigger than one chunk, or an upload interrupted halfway: the finished track plays back whole; a half-uploaded track is not listed as playable; files over 25 MB or not mp3 are refused with a message. (Tasks 4 and 10 tests.)
5. A song deleted while it is in a gig's setlist: it disappears from the setlist and the gig still opens. (Task 4 test.)

Known and accepted: two people changing the same song at the same moment means the last save wins.

### Task 2: Transposition

**Files:**

**Interfaces:**
- Produces:

  - `semitonesBetween(fromKey: string, toKey: string): number` — 0..11, using the root only (`"Em"` → E). Throws on an unknown key.
  - `prefersFlats(key: string): boolean` — true for roots F, Bb, Eb, Ab, Db, Gb and for minor keys Dm, Gm, Cm, Fm, Bbm, Ebm.

### Task 3: Chord sheet parsing

**Files:**
- Create: `src/shared/sheet.ts`, `tests/shared/sheet.test.ts`

**Interfaces:**
- Consumes: `transposeChord`, `prefersFlats`, `semitonesBetween` from Task 2.
- Produces:
  - `type SheetPart = { type: "text"; text: string } | { type: "chord"; chord: string }`
  - `type SheetLine = { kind: "section"; label: string } | { kind: "line"; parts: SheetPart[] }`
  - `parseSheet(content: string): SheetLine[]` — normalises `\r\n`, removes `[tab]`/`[/tab]`, turns `[ch]X[/ch]` into chord parts, and treats a line that is only `[Something]` (not `ch`/`tab`) as a section.
  - `transposeContent(content: string, fromKey: string, toKey: string): string` — rewrites every `[ch]…[/ch]` chord. To keep columns aligned: when a chord gets longer, remove that many spaces right after its `[/ch]` if they exist; when it gets shorter, add spaces there, but only if more text follows on the same line (never trailing spaces).
  - `markupFromPlainText(text: string): string` — for pasted chords without markup. A line is a chord line when it has at least one token and every token is a chord (by Task 2's pattern), `x2`-style repeat, `|` or `-`. Chord tokens on chord lines get wrapped in `[ch]…[/ch]`, other lines are unchanged.

- [ ] **Step 1: Write failing tests**

```ts

  { kind: "line", parts: [{type:"chord",chord:"C"},{type:"text",text:"    "},{type:"chord",chord:"G"}] },
  { kind: "line", parts: [{type:"text",text:"Hello there"}] },

expect(transposeContent("[ch]G[/ch]    [ch]C[/ch]", "G", "Bb")).toBe("[ch]Bb[/ch]   [ch]Eb[/ch]");

expect(transposeContent("[ch]G[/ch]", "G", "G")).toBe("[ch]G[/ch]");
```

### Task 4: Storage

**Files:**
- Create: `src/shared/types.ts`, `netlify/functions/lib/kv.ts`, `netlify/functions/lib/repo.ts`, `tests/server/repo.test.ts`

**Interfaces:**
- Produces in `types.ts`:
  - `Song { id; title; artist; sourceUrl: string | null; originalKey; bandKey; capo: number; content; updatedAt: string }`
  - `SongInput = Omit<Song, "id" | "updatedAt">`
  - `Gig { id; name; date /* YYYY-MM-DD */; songIds: string[] }`, `GigInput = Omit<Gig, "id">`
  - `Track { id; title; size: number; parts: number; uploadedParts: number; createdAt: string }`
  - `ImportedSong = Omit<SongInput, "bandKey">`
- Produces in `kv.ts`: `interface KV { getText(k): Promise<string|null>; setText(k, v): Promise<void>; getBytes(k): Promise<ArrayBuffer|null>; setBytes(k, v: ArrayBuffer): Promise<void>; delete(k): Promise<void>; list(prefix): Promise<string[]> }`, `memoryKV(): KV`, `blobsKV(): KV` (store name `"band"`, using `getStore` from `@netlify/blobs`).
- Produces in `repo.ts`: `makeRepo(kv: KV)` returning:
  - `listSongs(): Promise<Song[]>` (sorted by title, case-insensitive), `getSong(id)`, `createSong(input)`, `updateSong(id, patch: Partial<SongInput>)`, `deleteSong(id)` (also removes the id from every gig).
  - `listGigs(): Promise<Gig[]>` (newest date first), `getGig(id)`, `createGig`, `updateGig(id, patch)`, `deleteGig(id)`. `getGig` drops song ids that no longer exist.
  - `listTracks(): Promise<Track[]>` (only where `uploadedParts === parts`, newest first), `createTrack({title, size})` (validates `size <= 26_214_400`, sets `parts = ceil(size / 3_145_728)`), `putTrackPart(id, n, bytes)` (rejects `n` out of range or a part over 3_145_728 bytes; increments `uploadedParts` when the part is new), `getTrackPart(id, n)`, `deleteTrack(id)` (deletes record and parts).
  - Missing ids return `null` from getters; mutations on missing ids throw `NotFoundError`. Invalid input throws `ValidationError(message)`.
  - Keys: `songs/{id}`, `gigs/{id}`, `tracks/{id}`, `audio/{id}/{n}`. Ids from `crypto.randomUUID()`.
